## Lock protocol limits

The 30-second limits apply separately to process/repository acquisition, the shared executor lock and Snowflake lock acquisition. They are not a guaranteed 30-second whole-save deadline; existing statement/network limits still apply. Waiting on ordinary read queries is outside this write-acquisition policy. No timeout is extended. A COMMIT communication error reports an unknown outcome, preserves the request identity and forbids blind re-save; a subsequent rollback attempt does not prove that COMMIT never happened. Restoration failure blocks reuse of the executor session and reports committed state if the business transaction already completed.

Implementation basis: [Snowflake LOCK_TIMEOUT](https://docs.snowflake.com/en/sql-reference/parameters#lock-timeout) and [ALTER SESSION SET/UNSET](https://docs.snowflake.com/en/sql-reference/sql/alter-session). Parameter changes are outside the owned business transaction, not inside row loops. The offline legacy cursor adapter is not a real company execution path; real application construction uses ConnectorExecutor or SnowparkExecutor.
